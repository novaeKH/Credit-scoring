# Credit Scoring

Прогнозирование платёжных затруднений клиента на
[Home Credit Default Risk](https://www.kaggle.com/competitions/home-credit-default-risk).
В проекте 307 511 размеченных клиентов, семь исходных таблиц и 226 признаков
после агрегации истории. TARGET=1 встречается у 8.07% клиентов. В определении
TARGET есть задержка более X дней по одному из первых Y платежей; значения
X и Y не раскрыты, поэтому конкретный горизонт дефолта здесь не задаётся.

Основные вопросы: насколько полезен простой baseline, что дают дополнительные
таблицы и соответствуют ли вероятности наблюдаемой частоте TARGET=1.

## Результаты

Holdout — **61 503 клиента**. Модели обучены на одинаковой части из 184 506
клиентов; ещё 61 502 используются только для калибровки.

| Модель | ROC-AUC | Average Precision | Brier score ↓ |
|---|---:|---:|---:|
| Logistic Regression, все признаки | 0.7729 | 0.2634 | 0.066811 |
| CatBoost, только заявка | 0.7683 | 0.2587 | 0.067078 |
| CatBoost, заявка + бюро | 0.7725 | 0.2699 | 0.066614 |
| CatBoost, вся история | 0.7859 | 0.2870 | 0.065711 |
| CatBoost, вся история + калибровка | 0.7859 | 0.2870 | 0.065691 |

AP рассчитана через `average_precision_score`, а не трапецеидальный PR-AUC.

В первом варианте Logistic Regression обучалась без масштабирования и
выдавала предупреждение о сходимости; ROC-AUC был 0.6451. Теперь числа проходят
импутацию и StandardScaler внутри Pipeline, категории — one-hot. C выбран
из 0.1 и 1.0 на CV, class weights не используются. Исправленный baseline
получил ROC-AUC **0.7729**. Размер train и кодирование также изменились,
поэтому весь прирост нельзя приписать только масштабированию.

## Вклад истории

Три одинаковых стратифицированных фолда на обучающей части. Параметры CatBoost
фиксированы для всех вариантов: 500 деревьев, depth=6, learning_rate=0.05.

| Набор | Признаков | CV ROC-AUC: среднее ± std |
|---|---:|---:|
| Заявка | 125 | 0.7610 ± 0.0014 |
| Заявка + бюро | 141 | 0.7672 ± 0.0021 |
| Вся история | 226 | 0.7825 ± 0.0025 |

Полная история дала более заметную прибавку, чем добавление одного бюро.
Числа по каждому фолду сохранены в `reports/portfolio/cv_results.csv`.
Время обучения в этом файле — длительность конкретного запуска, а не отдельный
сравнительный benchmark скорости.

## Признаки и обработка данных

- **Заявка:** исходные поля, отношения кредита, дохода и аннуитета; специальное
  значение 365243 в DAYS_EMPLOYED заменено на NaN.
- **Бюро:** число кредитов, задолженность, активные договоры и месяцы просрочки.
- **POS и кредитные карты:** сначала история договора, затем агрегаты клиента.
- **Платежи:** части одного платежа объединяются до расчёта задержки и недоплаты.
- **Предыдущие заявки:** суммы, доли одобрений и отказов, интервалы дат.

Исходная логика агрегаций сохранена и вынесена в `src/credit_scoring/features.py`.
Признаки HAS_*_HISTORY отделяют отсутствие записи в источнике от нулевого
значения показателя. После объединений осталось 307 511 строк, повторов ID
и бесконечных значений нет. В ноутбуке есть таблицы пропусков и качества данных.

## Валидация и калибровка

Разбиение стратифицировано, seed=42: 60% train, 20% calibration, 20% holdout.
На train используются три CV-фолда. Импутация, масштабирование и one-hot
обучаются только на train каждого фолда. Агрегации не используют TARGET и
строятся отдельно для каждого клиента.

Состав holdout совпадает с validation из первой версии проекта, где его уже
использовали при выборе моделей. Это повторная оценка исправленного подхода,
а не новый слепой тест. В открытых данных нет дат заявок для временного split.

Для полного CatBoost обучена логистическая калибровка от logit вероятности,
использующая только calibration-часть. Основной вариант CatBoost и
калиброванный вариант оцениваются по заранее выбранному плану.
Brier score снизился с 0.065711 до 0.065691. Разница небольшая: калибровка уточнила вероятности, но не изменила ранжирование.
В ноутбуке показаны калибровочная кривая, десять групп риска и качество
клиентов с историей бюро и без неё.

Порог выдачи кредита и финансовый эффект не рассчитывались: открытый набор
не задаёт стоимость ошибок и условия продукта.

## Воспроизведение

Использован Python 3.11. Скачать данные соревнования после получения доступа
на Kaggle и распаковать CSV в `data/`. Данные в Git не включены.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# macOS / Linux, из корня проекта
export PYTHONPATH=src
export OPENBLAS_NUM_THREADS=2
export OMP_NUM_THREADS=2
python -m credit_scoring.prepare --data-dir data
python -m credit_scoring.experiment
```

В PowerShell переменная задаётся как `$env:PYTHONPATH="src"`.
В ноутбуках расчёты и графики строятся из сохранённых агрегированных отчётов:
их можно выполнить без повторного обучения. Открыть их можно в Jupyter или
VS Code с окружением проекта. Индивидуальные holdout-предсказания, состав
разбиений, подготовленные таблицы и новые веса сохраняются локально и исключены
из Git.
